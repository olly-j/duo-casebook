---
name: development-spine
description: Work safely and efficiently in a repository using the AI Development Spine.
---

Read `AGENTS.md` and `docs/README.md`, run `./dev orient`, define the outcome
and risk-proportionate evidence, then use available tools and AI capabilities
within scope. Before handoff, run `./dev audit`, `./dev verify --lane
<A|B|C>`, and use `./dev evidence --lane <A|B|C>` as the report skeleton.

Run `./dev ecosystem` when external skills, personas, standards, or tools may
apply. Select the smallest reviewed capability below project authority; a
catalog entry is not permission to install or activate it.

Proactively recommend better quality, lower-cost, faster, or safer approaches.
This optional skill never replaces the repository contract or human gates.

For a resumed task, use the compact `workflow resume` output and inspect its
retained results before rerunning. Refresh only needed capabilities at the
actual decision boundary. Follow the lazy freshness/reuse rules in `AGENTS.md`;
no polling, full-context reload or repeated broad preflight is required.

For iOS tasks, admission/resume includes `./dev apple-skills check` before relying
on Apple guidance, and each applicable `route` verifies again at use. A retained
workflow checkpoint or old cache is not newest-toolchain evidence. Review/adopt
changed guidance as the invoking engineering agent under owner authorization to
keep current; follow the Apple router and preserve separate product/release gates.
